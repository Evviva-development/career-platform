# Платформа обучения и оценки персонала ПМУ «Эввива» — прототип

Кликабельный прототип платформы для онбординга, обучения и оценки компетенций руководителей и кандидатов на ключевые должности. Построен по двум документам: «Регламент оценки компетенций» и «Модули оценки управленческих компетенций».

**Что внутри:** 8 модулей и 54 критерия с описаниями «что нужно знать и уметь», требования для профильных и непрофильных должностей из протоколов регламента, протоколы и листы заключений по каждому модулю, сводная ведомость, итоговый лист и решение комиссии.

> Это прототип. Все данные демонстрационные (люди, баллы, решения). Сервера нет: данные хранятся только в браузере (localStorage).

## Как запустить

Откройте `index.html` в браузере. Ничего устанавливать не нужно.

## Публикация через GitHub Pages

1. Загрузите содержимое этой папки в корень репозитория. Названия папок `css`, `js`, `assets` пишутся **маленькими буквами**: GitHub различает регистр.
2. Откройте **Settings → Pages**, выберите **Deploy from a branch**, ветку `main`, папку `/ (root)` и нажмите **Save**.
3. Через 1–3 минуты сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

На бесплатном тарифе Pages работает только для публичных репозиториев, и сайт виден всем, у кого есть ссылка.

### Как обновить версию
Перетащите новые файлы с той же структурой папок через **Add file → Upload files** и нажмите **Commit changes**. Файлы с такими же именами заменятся. Если страница не обновилась, нажмите **Ctrl + F5**.

## Структура

```
index.html        — каркас страницы
css/style.css     — стили в фирменных цветах «Эввива»
js/data.js        — данные: 8 модулей и 54 критерия, тесты, пороги, должности, ступени, демо-сотрудники
js/app.js         — логика: расчёт баллов, экраны ролей, обработка действий
assets/logo.png   — логотип
```

## Роли (кнопки «Смотреть как» вверху)

| Роль | Что делает |
|---|---|
| **Сотрудник** | Видит свой путь оценки и 8 модулей; изучает темы, проходит тесты или сообщает о готовности к оценке; после решения видит общий балл, ступень и план развития |
| **Оценщик** | Выбирает свой модуль (у каждого модуля свой ответственный по регламенту), ставит баллы 1–5, Н/О или Н/П, заполняет лист заключений, завершает оценку модуля |
| **Комиссия / HR** | **Сводная ведомость**: все сотрудники × 8 модулей, общий балл, вывод, ступень, фильтры, копирование в Excel. **Итоговый лист**: результаты по модулям, риски, заключения, решение комиссии, план развития, утверждение ГД |
| **Настройки** | Пороги и веса модулей; требования по каждому критерию; должности и их профильные модули; ступени роста; банк вопросов |

## Куда попадают результаты

- **Ответы на тест** сохраняются у модуля сотрудника. Оценщик видит их в протоколе («Тест: X из Y» у каждого критерия и полный ответ на кейс).
- **Баллы оценщика** формируют средний балл модуля и сразу появляются в **сводной ведомости** (Комиссия / HR).
- **Общий балл** считается в **итоговом листе**: это среднее из средних баллов оценённых модулей (с весами из настроек, по умолчанию одинаковыми).
- Сотрудник видит итоги только после решения комиссии.

## Правила расчёта (по регламенту)

- Шкала 1–5. «Н/О» и «Н/П» не заменяются нулём и исключаются из делителя.
- Средний балл модуля равен сумме баллов, делённой на число оценённых применимых критериев.
- Требование «Нет» для данного типа должности означает, что критерий автоматически получает «Н/П».
- Профильность определяется по должности: у каждой должности свой набор профильных модулей (Настройки → Должности и профили).
- Обязательными по умолчанию считаются все критерии профильного модуля. Если балл по ним ниже минимума, фиксируется дефицит.
- Система **предлагает** вывод и ступень, а решение принимает комиссия и утверждает генеральный директор.

## Тесты

Место под тесты есть во всех 8 модулях. Вопросы добавляются в `js/data.js` в массив `QUESTIONS`, кейсы — в `CASES`.
Пока заполнен только модуль 4 (демонстрационные вопросы, требуют утверждения). По остальным модулям сотрудник видит структуру будущего теста и может сообщить о готовности к оценке.

Формат вопроса:
```js
{id:'q16', m:'m1', c:'m1c1', text:'Текст вопроса', o:['Вариант 1','Вариант 2','Вариант 3','Вариант 4'], a:0}
// m — модуль, c — критерий (m1c1 = модуль 1, критерий 1), a — номер правильного варианта, считая с 0
```

## Что требует утверждения

- [ ] Тесты по модулям 1–3 и 5–8, проверка демо-вопросов модуля 4
- [ ] Пороги (сейчас 4,0 и 3,0) и минимальный балл по обязательным критериям (3)
- [ ] Должности и их профильные модули
- [ ] Названия ступеней роста и их пороги
